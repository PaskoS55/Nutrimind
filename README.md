# NutriMind by Pasko

Переносимый исходный проект демонстрационного веб-сервиса персонального питания NutriMind.

Версия расчётной архитектуры: `0.1.1-draft`. Проект предназначен для продолжения разработки и проверки. Он не готов к публикации или использованию для реальных медицинских рекомендаций.

## Технологии

- Next.js `16.2.6`
- React `19.2.6`
- Vinext `0.0.50`
- Vite `8.0.13`
- TypeScript `5.9.3`
- Node.js `>=22.13.0`
- npm и `package-lock.json`
- Node.js Test Runner для автоматических тестов
- Drizzle ORM `0.45.2`; рабочая схема базы пока не реализована

## Требования

- Node.js `22.13.0` или новее в пределах совместимой основной версии
- npm
- Для вспомогательных Sites-скриптов: Linux, `bash`, `flock`, `curl`, GNU `timeout` и `sha256sum`

Обычная локальная установка и запуск не требуют учётной записи Sites, токенов или секретных переменных среды.

## Установка

```bash
npm ci
```

Для Linux также доступна ограниченная по времени установка:

```bash
npm run install:ci
```

## Локальный запуск

```bash
npm run dev
```

После запуска открыть адрес, который напечатает Vite. Текущий проект использует один маршрут `/`, а переходы между главной, анкетой и отчётом выполняются состоянием React на клиенте.

## Сборка

```bash
npm run build
```

Сборка дополнительно проверяет наличие ESM Worker с `default.fetch` и корректного манифеста в `dist/`.

## Запуск собранной версии

```bash
npm run start
```

## Тесты

```bash
npm test
```

Команда выполняет производственную сборку и запускает все тесты из `tests/*.test.mjs`. Ожидаемый результат для версии `0.1.1-draft`: `31 passed / 0 failed / 0 skipped`.

## Маршруты и экраны

Физический маршрут сейчас один: `/`.

В `app/page.tsx` находятся:

- главная страница;
- пятишаговый демонстрационный интерфейс анкеты;
- страница персонального отчёта с вкладками;
- демонстрационные экраны обзора, тренера и администратора;
- демонстрационное окно входа.

Полные девять разделов утверждённой анкеты и все разрешённые ветвления сохранены в `docs/NUTRIMIND_SURVEY_SPEC.md` и `data/survey-schema.json`. Они пока не подключены полностью к пятишаговому экрану. Новые вопросы про шаги, бытовую активность, RPE и длительность каждой тренировки в двойной день не добавлены, поскольку требуют отдельного утверждения.

## Что пока является демонстрационным

- авторизация и регистрация;
- сохранение ответов анкеты;
- пятишаговый экран анкеты;
- значения и тексты видимого персонального отчёта;
- расчёт КБЖУ в интерфейсе;
- подбор продуктов и дневного меню;
- кабинеты пользователя, тренера и администратора;
- скачивание PDF;
- база данных и постоянное хранение;
- AI-функции, лабораторные данные, фотографии еды и носимые устройства.

Файлы `data/demo-athlete-profile.json` и `data/demo-report.json` содержат прозрачный демонстрационный сценарий для разработки. Это не данные реального пользователя.

## Медицинские ограничения

Проект нельзя использовать для реальных медицинских решений, пока не завершены клиническая проверка, safety-скрининг, реализация правил и независимая валидация.

Запрещено:

- ставить диагнозы;
- подтверждать дефициты без подходящих числовых анализов;
- автоматически менять лечебную диету;
- автоматически снижать энергию до утверждения safety-скрининга;
- показывать несовершеннолетним числовые КБЖУ и меню с порциями без специалиста;
- допускать продукт при конфликте с аллергией или медицинским ограничением;
- представлять расчётный стартовый ориентир как точную потребность;
- использовать демонстрационный отчёт как персональную рекомендацию.

При конфликте правил приоритет имеют:

1. аллергии;
2. медицинские ограничения;
3. непереносимости;
4. исключённые продукты;
5. нелюбимые продукты;
6. рейтинг пищевой ценности.

Актуальные ограничения и расчётные правила описаны в `docs/CALCULATION_CORE_SPEC.md`, `docs/PRODUCT_DATABASE_SPEC.md`, `docs/RECOMMENDATION_RULES_SPEC.md` и `docs/TEST_SCENARIOS.md`.

## Переменные среды

Текущий демонстрационный проект не требует секретов. Файл `.env.example` оставлен без секретных значений как шаблон для будущих интеграций. Реальные токены, ключи и медицинские данные нельзя коммитить или помещать в экспорт.

## Перенос между средами

Архив не содержит `node_modules`, `dist`, генерируемый кэш `.vinext`, временные файлы, журналы, локальные `.env` или историю Git. Манифест `.openai/hosting.json` в экспортируемом пакете не содержит идентификатор действующего сайта, поэтому локальная работа с архивом не меняет текущий проект Sites.
